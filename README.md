# voip_lan — голосовой чат с GUI для локальной сети (Radmin VPN)

P2P-голосовой чат без центрального сервера, с графическим интерфейсом
на egui. Каждый клиент равноправен: сам находит остальных участников
в сети и шлёт им звук напрямую по UDP. Один exe-файл, никаких
конфигов, никакого следа в реестре или AppData.

## Интерфейс

Сверху вниз:

1. **Имя** — текстовое поле, редактируется только пока не подключены
2. **Список собеседников** — у каждого свой слайдер громкости
   (0.0–2.0), можно сделать конкретного человека тише/громче независимо
   от остальных
3. **Микрофон** — слайдер собственной громкости (насколько громко вас
   слышат остальные)
4. **Микрофон / Звук** (зелёные кнопки) — мьют микрофона и мьют всего
   входящего звука. Зелёный = не замьючено, красный = замьючено
5. **Выпадающие списки устройств** — выбор микрофона и наушников/колонок.
   При смене устройства звук перезапускается автоматически, без
   отдельной кнопки — при этом собеседники не отключаются (discovery
   продолжает работать)
6. **Подключиться / Отключиться** — зелёная/красная кнопка, включает
   и выключает всё сразу (discovery + звук)
7. **Логи** — панель с сообщениями о происходящем (кто подключился,
   ошибки устройств и т.д.)

## Возможности

- **Обнаружение участников** через UDP broadcast — не нужно вручную вводить IP
- **Opus-кодирование голоса** — тот же кодек, что использует Mumble:
  48 кГц моно, фреймы по 10 мс, ~40 кбит/с
- **Честный микшер**: голоса нескольких говорящих одновременно
  складываются как звуковые волны (с учётом персональной громкости
  каждого), а не идут вперемешку кусками
- **Автоматическое переподключение** звука при смене устройства —
  без отдельной кнопки
- **Никаких файлов настроек** — только то, что видно в самом окне
  программы

## Сборка

Локально (нужен установленный Rust — https://rustup.rs):

```bash
cargo build --release
```

Бинарник появится в `target/release/voip_lan` (`voip_lan.exe` на Windows).

### Кросс-компиляция под Windows с Linux/macOS

```bash
rustup target add x86_64-pc-windows-gnu
cargo build --release --target x86_64-pc-windows-gnu
```

### Через GitHub Actions — без установки Rust вообще

В проекте настроены два workflow (папка `.github/workflows`):

- **`build.yml`** — собирает Windows .exe при каждом push в `main`/`master`
  или вручную кнопкой "Run workflow" во вкладке **Actions**. Готовый файл
  забирается там же, в разделе **Artifacts** у завершённого запуска.
- **`release.yml`** — при создании тега вида `v1.0` автоматически собирает
  .exe и публикует его в разделе **Releases**:
  ```bash
  git tag v1.0
  git push origin v1.0
  ```

Сборка происходит на серверах GitHub, не на вашем компьютере — Rust
локально можно не ставить вообще.

## Известный нюанс сборки: CMake и libopus

Крейт `opus` собирает libopus из исходников через CMake (это делает
`audiopus_sys`), если в системе нет готовой библиотеки — именно так
происходит на раннерах GitHub Actions. Начиная с CMake 3.31 сборка
такого рода падает с ошибкой `Compatibility with CMake < 3.5 has been
removed`. Лечится переменной окружения:

```
CMAKE_POLICY_VERSION_MINIMUM=3.5
```

Она уже прописана в обоих workflow-файлах. Если собираете локально и
ловите ту же ошибку — задайте переменную перед `cargo build`:

```bash
# Linux/macOS
CMAKE_POLICY_VERSION_MINIMUM=3.5 cargo build --release

# Windows PowerShell
$env:CMAKE_POLICY_VERSION_MINIMUM="3.5"; cargo build --release
```

## Технические детали

| Параметр | Значение |
|---|---|
| GUI | egui / eframe (нативный рендер, один exe) |
| Кодек | Opus, `Application::Voip` |
| Частота дискретизации | 48000 Гц (моно) |
| Размер фрейма | 480 сэмплов = 10 мс |
| Битрейт | 40 кбит/с |
| Порт голоса | 47531 (UDP) |
| Порт обнаружения | 47532 (UDP) |

## Архитектура (для тех, кто будет дорабатывать код)

- `state.rs` — общее состояние (`SharedState`), расшаривается между GUI
  и фоновыми потоками через `Arc`
- `network.rs` — discovery (обнаружение участников по UDP broadcast)
- `audio.rs` — захват/воспроизведение звука, Opus, микшер, перечисление
  устройств
- `gui.rs` — само окно на egui
- `settings.rs` — константы (порты, битрейт, таймауты)

Discovery и звук управляются **независимыми** флагами остановки:
`SharedState::running` относится только к discovery, а у каждой
голосовой сессии свой `voice_running` (см. `audio::VoiceHandles`).
Это позволяет перезапускать звук при смене устройства, не отключая
участников от обнаружения.

## Чего пока нет (возможные следующие шаги)

- **Push-to-talk** — сейчас микрофон передаётся постоянно, если не
  нажата кнопка мьюта
- **Шифрование трафика** — для доверенной локалки через Radmin VPN
  обычно не критично, но можно добавить (например, через `libsodium`)
- **Лок-фри буферы** вместо `Mutex` в аудио callback'ах — для хобби-проекта
  на несколько человек в LAN блокировки не создают заметных проблем,
  но это не production-grade решение

## Портативность

Все данные — только в самом окне программы (текстовое поле, слайдеры,
выпадающие списки). Никаких записей в реестр Windows или `%APPDATA%`.
Для полностью автономного .exe используется статическая линковка CRT
(см. `.cargo/config.toml` и переменную `RUSTFLAGS` в GitHub Actions) —
бинарник не требует Visual C++ Redistributable на целевой машине.
