# voip_lan — голосовой чат для локальной сети (Radmin VPN)

P2P-голосовой чат без центрального сервера. Каждый клиент равноправен:
сам находит остальных участников в сети и шлёт им звук напрямую по UDP.
Один exe-файл, никаких конфигов, никакого следа в реестре или AppData.

## Возможности

- **Обнаружение участников** через UDP broadcast — не нужно вручную вводить IP
- **Opus-кодирование голоса** — тот же кодек, что использует Mumble:
  48 кГц моно, фреймы по 10 мс, ~40 кбит/с — компактно и с хорошим качеством
- **Честный микшер**: если говорят несколько человек одновременно, их голоса
  складываются как звуковые волны (с ограничением клиппинга), а не идут
  вперемешку кусками, как в первой версии
- **Никаких файлов настроек** — только имя пользователя, спрашивается
  при запуске в консоли; если оставить пустым — сгенерируется автоматически
  (`User1234`)

## Сборка

Локально (нужен установленный Rust — https://rustup.rs):

```bash
cargo build --release
```

Бинарник появится в `target/release/voip_lan` (`voip_lan.exe` на Windows).

### Кросс-компиляция под Windows с Linux/macOS

```bash
rustup target add x86_64-pc-windows-gnu
cargo build --release --target x86_64-pc-windows-gnu
```

### Через GitHub Actions — без установки Rust вообще

В проекте уже настроены два workflow (папка `.github/workflows`):

- **`build.yml`** — собирает Windows .exe при каждом push в `main`/`master`
  или вручную кнопкой "Run workflow" во вкладке **Actions**. Готовый файл
  можно скачать там же, в разделе **Artifacts** у завершённого запуска.
- **`release.yml`** — при создании тега вида `v1.0` автоматически собирает
  .exe и публикует его в разделе **Releases** репозитория:
  ```bash
  git tag v1.0
  git push origin v1.0
  ```

**Где именно происходит сборка:** на серверах GitHub (их собственные
временные виртуальные машины — "runners"), а не на вашем компьютере.
Поэтому Rust локально не нужен вообще — редактировать код можно прямо
в веб-редакторе GitHub (нажать `.` на странице репозитория — откроется
VS Code в браузере) или в любом текстовом редакторе, закоммитить и
запушить изменения, а GitHub сам соберёт релизный .exe и отдаст его
на скачивание.

## Запуск

```
voip_lan.exe
```

Программа спросит имя в консоли (Enter — будет сгенерировано случайное).
Либо передать имя сразу аргументом:

```
voip_lan.exe Иван
```

Участники в одной сети Radmin VPN должны увидеть друг друга автоматически
в течение нескольких секунд.

Если обнаружение не работает (широковещательный пакет не проходит через
конкретный VPN-адаптер), укажите вторым аргументом адрес подсети Radmin —
обычно она вида `26.x.x.x/24`, тогда broadcast будет `26.x.x.255`
(точный адрес — команда `ipconfig` на интерфейсе Radmin VPN Adapter):

```
voip_lan.exe Иван 26.155.20.255
```

## Технические детали

| Параметр | Значение |
|---|---|
| Кодек | Opus, `Application::Voip` |
| Частота дискретизации | 48000 Гц (моно) |
| Размер фрейма | 480 сэмплов = 10 мс |
| Битрейт | 40 кбит/с |
| Порт голоса | 47531 (UDP) |
| Порт обнаружения | 47532 (UDP) |

## Чего пока нет (возможные следующие шаги)

- **Push-to-talk** — сейчас микрофон передаётся постоянно (open mic)
- **Шифрование трафика** — для доверенной локалки через Radmin VPN обычно
  не критично, но можно добавить (например, через `libsodium`)
- **Лок-фри буферы** вместо `Mutex` в аудио-потоках — сейчас в реалтайм
  callback'е воспроизведения происходит блокировка мьютекса, что в теории
  может изредка вызывать микро-заикания под нагрузкой; для хобби-проекта
  на пару-тройку человек в LAN это не критично

## Портативность

Все данные — только в аргументах командной строки / вводе в консоли.
Никаких записей в реестр Windows или `%APPDATA%`. Для полностью
автономного .exe используется статическая линковка CRT (см.
`.cargo/config.toml` и переменную `RUSTFLAGS` в GitHub Actions) —
бинарник не требует Visual C++ Redistributable на целевой машине.
